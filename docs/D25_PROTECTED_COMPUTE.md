## How the new commercial desktop build works

The old React browser application imported quantum simulation and research algorithms into workers. Tauri packaging, disabled source maps, minification, encryption, code signing, or Windows Store DRM cannot make a shipped algorithm confidential to a determined owner of the device.

The commercial Windows Tauri shell now compiles a **different entry point**:

- \`apps/web/desktop/index.html\` -> \`src/secure/main.tsx\` -> Firebase customer authentication + **server-only protected compute UI**
- \`apps/web/dist-desktop\` is the sole frontend payload referenced by \`src-tauri/tauri.conf.json\`. It deliberately contains no \`apps/engine/src\` modules or simulation workers.
- The Vite commercial plugin rejects imports of solver modules, and \`scripts/verify-commercial-bundle.mjs\` fails the build if it detects worker files, sourcemaps, private keys or known solver signatures.
- The old \`apps/web/dist\` is used only for the separate developer/website application. **Never pack or distribute that web dist as the commercial desktop.**
- The Tauri commercial app exposes no local quota commands or general-purpose native execution IPC. Its Content Security Policy does not allow workers.

The new protected UI currently provides **bounded OpenQASM circuit execution and MaxCut QAOA**. It does not yet reproduce the entire original laboratory/industry GUI toolset, and must not be marketed as full functional parity with the developer web UI. Reintroduce other scientific workbenches only with comparable authenticated backend endpoints.

## Protected cloud execution service

The deployed Firebase function \`d25Compute\` should:

1. Verify a fresh Firebase ID token, verified email and enabled Firebase Auth user. The desktop must not provide a UID or credential in the job payload.
2. Read the paid subscription from private Firestore collection \`d25Accounts\`. Refunded, revoked, disabled or expired customers are denied.
3. Validate the job schema and independent solver work limits **before** reserving compute.
4. Within one Firestore transaction, check the subscription document, reserve one of 20 execution launches and persist a unique request ID. The 21st request is denied with a five-hour cooldown. Retries of an identical request ID do not create a second launch. Desktop local clocks/cookies/IPs do not govern this allowance.
5. Run \`functions/private-engine.cjs\`, compiled from the existing bounded industry contract on **trusted server infrastructure only**, and return results. Never send executable source or numerical solver modules to clients. After a failure the reserved launch is still spent.
6. Do not accept a request merely because the UI says \`active\`. Each computation has a fresh server authorization and quota decision.

The server engine bundle is generated by \`npm run build:private-engine\`, written only to \`functions/private-engine.cjs\`, and excluded from Git. The Firebase CLI invokes the compilation before functions deployment. Keep the deployed server environment and service account credentials under MAH Quantum control.

**IMPORTANT:** The repository currently contains the original quantum engine source publicly. The commercial installer no longer ships the engine, but private intellectual-property protection for **future unpublished code** requires a private repository. Switching GitHub to private later does not erase earlier public copies, forks or downloads. Consider a **new private compute-engine repository** and a public frontend-only repository so deployment logs, CI artifacts, forks, releases, source packages and Git history do not re-expose confidential IP.

## Deploy/build workflow

Setup Firebase Authentication, Firestore, Razorpay TEST subscription plan/webhook, and the D25 Google admin role using [Firebase monthly setup](D25_FIREBASE_MONTHLY_SETUP.md). The Cloud Functions deployment requires a Firebase project with supported **Blaze / billing-enabled** functions, which can incur server compute and storage charges. No unbounded free hosting is promised.

Add the public Firebase web config and secure Cloud Function URLs to \`apps/web/.env.production.local\` (gitignored):

\`\`\`text
VITE_D25_FIREBASE_API_KEY=YOUR_PUBLIC_FIREBASE_API_KEY
VITE_D25_API_BASE=https://asia-south1-YOUR_PROJECT_ID.cloudfunctions.net/d25Api
VITE_D25_COMPUTE_API_BASE=https://asia-south1-YOUR_PROJECT_ID.cloudfunctions.net/d25Compute
\`\`\`

Never add service-account private keys, Razorpay Key Secret, webhook secret, API bearer credentials or a local engine into the desktop bundle. The server's \`functions/.env.YOUR_PROJECT\` may contain:

\`\`\`text
D25_RAZORPAY_PLAN_ID_TEST=plan_REAL_TEST_ID
D25_ALLOWED_ORIGINS=https://your-approved-website.example
D25_COMPUTE_ALLOWED_ORIGINS=https://your-approved-website.example
\`\`\`

The server-only payment credentials are configured through Firebase Secret Manager (see linked setup). **Leave live billing disabled.**

\`\`\`bat
npm ci
npm run build:private-engine
node --test functions/test/compute-policy.test.cjs functions/test/compute-engine.test.cjs
npm run build:desktop
npm run verify:commercial
npm run desktop:icons

node scripts/d25_store_preflight.mjs --enforce

The final \`--enforce\` command **must remain NO_GO** until customer testing, Store submission, independent numerical validation and all business controls are certified. A successful \`.exe\` or \`.msi\` build is not an approved release.

For Firebase deployment, install dependencies and run \`firebase deploy --only functions,firestore:rules\` in the **correct dedicated project**. The \`firebase.json\` predeploy hook builds the private server solver. A deployment cannot be claimed until actual Firebase account/project connection is supplied and each HTTP endpoint has been smoke tested.

## End-to-end tests still required

- No engine or secret source appears in the **extracted** EXE/MSI/MSIX or Vite commercial assets, validated on a real Windows machine.
- Firebase test user signs in and pays; backend confirms a captured, correctly priced recurring period. Unauthorized, unpaid, revoked, expired, and disabled users all get 401/403.
- Two concurrent requests consume two credits; 21 concurrent requests permit at most 20; new requests after exactly five hours refill once. Firestore outages fail closed. Duplicate UUIDs yield 409.
- Circuit results match the independent NumPy/python reference for validated ideal circuit families; MaxCut optimization matches known classical optima. Enforce shots, qubits, source bytes, memory and CPU constraints under load.
- Mobile/Windows restarts, sign-out, long-running jobs, cancellation, timeouts, refunds and loss of connectivity are handled without accidentally granting free computation.
- Test Store MSIX clean-install/uninstall, WebView2, CPU/memory, upgrades, accessibility, customer recovery, privacy and support.
- Perform third-party security testing, dependency audits, server IAM review, account abuse testing, operational cost caps and incident drills.

## Limitations

Copied installer files, screenshots, JSON outputs and UI behavior can still be redistributed or recreated. An attacker with full device access can alter the frontend. **The security objective is not to make bytes impossible to copy; it is to keep confidential algorithms on trusted servers and refuse paid compute without a valid subscription.** No software distribution method makes reproduction literally impossible.

Cloud compute costs, network availability, latency and maintenance now affect customer usability. Document data retention and customer circuit privacy before commercial launch.
